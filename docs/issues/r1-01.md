## Результат

Користувач може пройти макет сценарію від введення до report; жоден fixture не видається за реальний аналіз.

## Код і файли

apps/web/app/page.tsx; app/cases/[caseId]/page.tsx; components/CaseForm.tsx; RecommendationCard.tsx; ReportSections.tsx; RoleCard.tsx; RunProgress.tsx

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. Створити Next.js + TypeScript app та install/dev/build commands.
2. Зробити форму required indication/mechanism та optional program data/modality/stage; пояснити scope.
3. Відобразити report-v1 fixture: recommendation/rationale, scope, 11 sections, role summaries, risks/unknowns/questions.
4. Додати loading/empty/validation/failed states та synthetic label.
5. Перевірити довгі тексти, вузький екран і доступність полів; передати screenshot на review.

## Критерії готовності

- [ ] Required fields перевіряються до запуску.
- [ ] Усі 11 sections і synthetic label видимі; missing data не приховані.
- [ ] Loading/failed/empty states працюють на mocks.
- [ ] npm run build проходить; report читається на desktop і вузькому екрані.

## Як перевірити

Відкрити fixture report, порожню форму й mock failed run; вручну перевірити довгий текст та всі секції.

## Що передати команді

R2 отримує список UI fields; R5 перевіряє повноту report rendering.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
