## Результат

Сайт запускає справжній analysis і показує збережений результат через один погоджений API.

## Код і файли

apps/web/lib/api.ts; types/; app/api/.../route.ts; app/cases/[caseId]/page.tsx

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. Взяти актуальну OpenAPI і реалізувати typed createCase/startRun/getRun/getReport.
2. Зробити server proxy з API_BASE_URL; LLM secrets не передавати у client bundle.
3. Form submit: create case → start run → poll status → load report_version.
4. Polling зупиняти на terminal status/cleanup; новий run лише за user action.
5. Показати stage/errors, handle 422/404/non-2xx/network failure; reload читає persisted result.

## Критерії готовності

- [ ] Один click створює один run.
- [ ] Failed run дає видиму помилку без нескінченного spinner.
- [ ] Completed report читається за правильною version.
- [ ] Повторне відкриття case не генерує report повторно без команди.

## Як перевірити

Пройти реальний API happy path та failed run; reload case; у network перевірити відсутність повторних start requests.

## Що передати команді

R2 отримує contract defects із точним request/response; R1-03 додає evidence/revisions.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
