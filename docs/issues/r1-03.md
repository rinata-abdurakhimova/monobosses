## Результат

Користувач перевіряє конкретний claim і бачить, як новий документ вплинув на висновок.

## Код і файли

apps/web/components/EvidenceDrawer.tsx; EvidenceUpload.tsx; RevisionComparison.tsx; lib/api.ts

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. Recommendation → claims → evidence → source: excerpt, locator, title/date/limitations/URL.
2. Позначити inference/unknown/user-provided/synthetic; private source не має fake URL.
3. Text і PDF upload за common endpoints, показати import errors без rerun.
4. Після import explicit rerun із parent_report_id; old report доступний.
5. Порівняти category/claims/rationale; unchanged recommendation показувати чесно.
6. Відобразити version і run metadata, readable failed states.

## Критерії готовності

- [ ] Від рішення можна перейти до exact excerpt.
- [ ] Text і PDF flow працюють; parsing/size errors показані.
- [ ] V1 і V2 відкриваються окремо.
- [ ] Категорія/claims before/after відповідають backend revision.
- [ ] Unknown/inference не відображаються як verified fact.

## Як перевірити

Synthetic safety update через UI; unrelated update; private upload без URL; unreadable/oversized PDF.

## Що передати команді

R1-04 розгортає той самий сценарій; R3/R5 перевіряють evidence/revision wording.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
