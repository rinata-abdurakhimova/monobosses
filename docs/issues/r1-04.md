## Результат

Команда має deployment URL, persistent reports і working UI/API/upload/revision.

## Код і файли

apps/web deployment config; backend deployment config у погодженні з R2; docs/deployment.md; README.md

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. Отримати від R2 production command/health/env/storage/auth; обрати hosting з доступних accounts.
2. Розгорнути API й frontend, HTTPS, API_BASE_URL, server-side auth, погоджені origins.
3. Перевірити persistence після restart; ephemeral disk — blocker, не прихований caveat.
4. Перевірити proxy/upload limits і background status polling; keys не у browser.
5. Пройти synthetic before/after і live input на deployment; перевірити error/source outage.
6. Записати URL, commands, env names, deployment/recovery steps і відомі limits без secrets.

## Критерії готовності

- [ ] Deployment URL відкриває повний user flow.
- [ ] API restart не стирає saved reports/evidence.
- [ ] Uploads/errors/revisions працюють поза localhost.
- [ ] Secrets не у bundle/docs; API захищений за контрактом.
- [ ] Deployment instructions дозволяють іншій учасниці відтворити release.

## Як перевірити

На deployed site input → report → source → upload → rerun → v1/v2; restart backend; перевірити один failed run.
