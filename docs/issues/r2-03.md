## Результат

Новий доказ створює нову версію, стара збережена; ті самі pipeline/config можна запускати на case manifests.

## Код і файли

services/api/src/vic/api/evidence.py; documents.py; pipeline.py; storage.py; evals/run.py; tests

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. Підключити text/PDF import R3 з type/size/errors; upload не запускає run автоматично.
2. POST run з parent_report_id перевіряє same case й snapshot; для MVP повний rerun.
3. Atomic report version, immutable parent, revision через stable claim keys/new evidence IDs.
4. Написати runner manifest → pipeline → per-case report/trace/usage/results; expectations/scoring надає R5.
5. Evidence-only не відкриває retrieval; evaluator labels/identity mapping не передаються у model payload.
6. Перевірити wrong parent, concurrent versions, restart, parsing failure.

## Критерії готовності

- [ ] V1 незмінний після v2.
- [ ] Revision має before/after і concrete changed claims/evidence.
- [ ] Wrong-case parent відхилено; upload failures зрозумілі.
- [ ] Runner повторно запускається documented command і зберігає config/snapshot/results.
- [ ] Без network retrieval у evidence-only.

## Як перевірити

Import safety evidence → rerun → перевірити v1/v2; import irrelevant evidence; wrong parent; runner на 2 synthetic cases.

## Що передати команді

R1-03 отримує revisions; R4-03 і R5-04 використовують rerun/runner.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
