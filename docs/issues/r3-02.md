## Результат

Система знаходить supporting/contradictory evidence для різних indication × mechanism, зберігаючи точні snapshots.

## Код і файли

services/api/src/vic/evidence/retrieval.py; connectors/pubmed.py; clinical_trials.py; open_targets.py; docs/source-registry.md

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. За офіційними docs перевірити access methods/limits й записати source registry.
2. Підключити PubMed/PMC, ClinicalTrials.gov; Open Targets для identity за потреби.
3. Normalize synonyms, ambiguous target повертає уточнення, не random choice.
4. Шукати efficacy, safety, negative/terminated studies та competitors.
5. Зберігати text/records/hash/retrieved_at і exact excerpts; abstract-only явно маркувати.
6. Cache, bounded retries, distinguish empty search/source outage; evidence-only не робить retrieval.
7. Підготувати два різні live cases; перевірити current investigational status кандидатів перед demo.

## Критерії готовності

- [ ] Live responses приводяться до common EvidencePack.
- [ ] Суперечливі дані не відкидаються.
- [ ] Відмова джерела має warning; не трактована як відсутність safety risk.
- [ ] Historical evaluation використовує допустимі frozen records, не later outcome.
- [ ] Source registry пояснює coverage/limits.

## Як перевірити

Запустити два inputs; відкрити sources й порівняти excerpt; симулювати outage; evidence-only run не викликає connectors.

## Що передати команді

R4/R5 отримують evidence packs; R2 підключає build_evidence_pack; R3-03 аудитор.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
