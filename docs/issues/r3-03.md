## Результат

Наявність цитати не маскує неправильний висновок; контрольні critical unsupported claims блокуються, evaluation має явні leakage flags.

## Код і файли

services/api/src/vic/evidence/audit.py; tests; evals/ leakage metadata; docs/source-registry.md

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. Structural checks IDs/excerpts/locators/provenance; common AuditResult output.
2. Semantic checks population/candidate/scope, human vs animal, association vs causal, support/contradiction.
3. Critical unsupported fact познач blocking; AI inference перевіряти через premises.
4. Аудит також викликається після chair для її нових claims.
5. З R5 підготувати деідентифікацію й blind guessing; original identity mapping не у model input.
6. Temporal flags перевіряють documented cutoff/as-of snapshots; uncertain leakage не видавати за controlled.

## Критерії готовності

- [ ] Контрольний mouse-result-as-human-efficacy claim виявлено.
- [ ] Dangling/misattributed citations виявлено.
- [ ] Audit reasons зрозумілі та мають evidence IDs.
- [ ] Blind packs не розкривають identity прямими URLs/IDs; відомі leakage failures позначені.
- [ ] Final chair claims можуть бути перевірені тим самим function.

## Як перевірити

Контрольні supported/contradicted/misattributed/unknown claims; ручний review critical facts; запис blind re-identification result.

## Що передати команді

R2 отримує audit hook; R5 — leakage metadata, R1 — displayable findings.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
