## Результат

Science/clinical outputs правильно реагують на вирішальні та нерелевантні докази; evaluation має перевірні предметні labels.

## Код і файли

services/api/src/vic/agents/science/ tests/prompts; evals/cases/ предметні expectations

Це очікувані шляхи реалізації; на момент планування код ще не створено. Використовуємо один package `vic`, contracts і LLM adapter R2.

## Що за чим робити

1. До model run записати expected claim changes для synthetic paired pack.
2. Перевірити negative, positive та irrelevant evidence; врахувати candidate/exposure/population relevance.
3. Зберегти stable claim keys; v2 пояснює конкретний changed premise.
4. Негативний candidate result не знищує весь mechanism; positive не усуває інші risks.
5. Передати R5 expected critical facts/risks, допустимі interpretations і limitations, позначені team-reviewed.
6. Розібрати предметні errors; tuning на development split.

## Критерії готовності

- [ ] Вирішальний update змінює відповідний claim із evidence.
- [ ] Нерелевантний update не створює штучного science change.
- [ ] Missing links і scope збережені.
- [ ] Expectations написані до оцінки output і не потрапляють у model prompt.

## Як перевірити

Три paired checks із ручним review claims; зафіксувати expected/actual mismatch та owner.

## Що передати команді

R5-04 отримує science/clinical expectations; R2/R3 отримують contract/evidence defects.

У PR: посилання на цю задачу, опис working behavior, commands/input/result перевірки та відомі обмеження. Не закривати live-задачу лише на mock output. API/schema change погодити з R2 і споживачами.
