# Issue #28: R5 role contracts and frontend support

Issue: https://github.com/rinata-abdurakhimova/monobosses/issues/28

The shared R2 contract originally registered only market, investment and chair
from R5. Four agreed IDs were missing from Python, OpenAPI and generated
TypeScript: failure_miner, investment_threshold, partnerships and ip_licensing.
The frontend label lookup also assumed every role was known, and its role cards
did not expose claims, risks or change conditions. Adding a label alone would
leave the OpenAPI validator rejecting the new role before rendering.

## Changes prepared by R1

- Added all four IDs to `vic.contracts.RoleId`, exported OpenAPI and regenerated
  frontend types. Existing science, translation, clinical and audit remain.
- Added names and initials for all seven R5 roles. The label table is exhaustive
  against generated RoleId, so future agreed enum additions require a label.
- Preserved role claims, risks, unknowns, change_conditions and section_content.
  Cards expose claim evidence, risk impact/next_check/supporting claims and the
  conditions that would change a position.
- Added a neutral fallback for future IDs at the display boundary, including IDs
  in disagreements. All other schema and reference validation stays active;
  backend validation still rejects unregistered IDs.
- Added `contracts/fixtures/report-r5.json`, generated by `vic.synthetic`, with
  all seven R5 roles and all four R3/R4 roles. It is a display fixture, includes
  explicit gaps, and does not execute or establish completion of expert nodes.
  The original v1/v2 fixtures and the 11 required sections remain unchanged.

## What R5 should return

Use these exact IDs with the shared Pydantic `RoleResult`:

| ID | Perspective |
| --- | --- |
| market | Market and commercial opportunity |
| investment | Finance and investment scenarios |
| failure_miner | Critical risks and failure modes |
| chair | Committee chair |
| investment_threshold | Investment conditions |
| partnerships | Partnerships |
| ip_licensing | Intellectual property and licensing |

Return summary, position, claims, risks, unknowns, change_conditions and a **list**
of SectionContent. Use existing SectionKey values; partners and IP do not require
extra report sections. Keep missing evidence explicit rather than creating
positive partner-interest or patent-rights claims. Source-backed claims must
retain evidence IDs from the shared pack, and claim IDs must be stable.

R2 must assemble the same claim/risk records in both role results and the
canonical Report lists, retaining pack evidence and sources. A section summary
alone is not enough for R1 to show the supporting analysis.

The existing chair signature returns `CommitteeDecision`, not `RoleResult`.
R2/R5 must agree how the actual chair decision is represented in `Report.roles`
as well as its canonical recommendation fields; do not invent a second chair
analysis just to populate the card. The synthetic fixture is only an example of
that display shape.

## Remaining R2/R5 integration

R2/R5 still need to agree the four new node input signatures and dependencies,
register their prompts with versions/hashes, and wire actual implementations
through RunContext and the shared adapter. R3 audits their claims and any new
chair claims. Enum/frontend support does not complete that runtime work.

R5's `codex/r5-ip-licensing` branch already adds IP_LICENSING to the enum; when
integrating, keep one member and preserve the other three additions here. R2 and
the consumers should review this shared-contract change before merging, as
required by the module ownership note. No merge or issue comment is performed
by this patch.

The current product mapper is synthetic-only. This patch does not enable live
analysis; live report mapping belongs to the API integration work.
